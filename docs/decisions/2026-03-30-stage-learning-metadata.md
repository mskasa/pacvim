# ステージへの学習メタデータ埋め込み方針

- Date: 2026-03-30
- Type: ADR
- Status: Active
- Author: masahiro.kasatani

## Context

PacVim を「Vim を学ぶツール」として位置づけるにあたり、各ステージがどのコマンドを練習するものかがゲーム内で伝わっていなかった。
プレイヤーはステージが始まると何を使えばよいか分からず、学習の意図が伝わりにくい状態だった。
この情報をどこに・どう持たせるかを決める必要があった。

## Decision

学習メタデータ（テーマ・コマンド一覧）を `Stage` struct のフィールドとして持たせる。
`PhaseReady`（準備画面）でこれらを表示し、プレイヤーがステージ開始前に練習内容を確認できるようにする。

```go
type Stage struct {
    Theme    string   // 学習テーマ（例: "基本移動"）
    Commands []string // 練習コマンドの説明（表示用文字列）
}
```

## Consequences

**メリット**
- ステージ定義（`InitStages`）とその学習コンテンツが同じ場所にまとまり、見通しが良い。
- 新しいステージを追加するときに `Theme`・`Commands` を自然に書くよう促せる。
- `renderer` は `stage.Commands` を表示するだけで良く、コマンド知識を持たなくてよい。

**トレードオフ**
- `Stage` struct がゲームロジック（マップ・敵・速度）と学習メタデータを両方持つことになる。
  将来的に学習メタデータが複雑化した場合は別 struct への分離を検討する。
- `Commands` は表示用の文字列なので、コマンドの機械的な管理（例: 「このステージで使えるコマンドを制限する」）には向かない。

## Alternatives Considered

- **`renderer` 側にハードコードする**: ステージ番号で分岐して表示内容を決める案。ステージ追加時に2箇所を変更する必要があり、採用しない。
- **別ファイル（YAML/TOML 等）に外出しする**: 柔軟だが、現時点では5ステージのシンプルな構成に対して過剰。採用しない。
